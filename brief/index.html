SecTor 2026 in 60 seconds

Across the three days, almost nothing presented was a brand-new class of attack. Instead, speaker after speaker showed familiar techniques (SSRF, credential theft, privilege escalation, prompt injection, Rowhammer, spyware exploits) running faster, cheaper and with less skill than before. Autonomous agents chained cloud attacks in minutes, a full intrusion demo cost about $500, and AI found tens of thousands of vulnerabilities faster than people could verify them. At the same time, the attack surface moved onto devices we already trust: AI models built into browsers, GPUs shared between workloads, and phones carrying our authenticators. The final day turned to control: agents quietly widening a narrow request into a public exposure, a fleet of military robots sharing one password, and data stolen today to decrypt with tomorrow's quantum computers. The defences that held up were the fundamentals: identity, least privilege, segmentation, deception, independent verification, and checking authority at the moment of action.

Twelve major findings

  1. Attack chains now complete in minutes.

    Agents connect old techniques (SSRF to the metadata service, credential theft, privilege escalation) without pausing. Detection that takes longer than the chain can't prevent it.

    ~3 min for a chain's critical steps; ~13 min average from a low-privileged key to admin. Both presented during the sessions.

    Cloud hardeningDeception
  2. Nation-state capability is commoditized.

    The things that once separated state operators from everyone else (money, teams, custom tools) are eroding. In 2026, US agencies warned of AI-written scripts aimed at the same PLC family Stuxnet targeted.

    “You are not defending against China: you are defending against $250 a month.” Source for the 2026 warning: CISA AA26-231A.

    Nation-state keynote
  3. Intrusion is cheap enough to try everywhere.

    A multi-agent demo went from one prompt to exfiltrating developer secrets in about 27 hours for about $500. Patching faster can't keep up with that economics; reducing what's reachable can.

    Figures presented during the session.

    Dark by defaultSecurity economics
  4. AI agents are identities nobody governs yet.

    Organizations are deploying agents faster than they can inventory, authenticate, scope or revoke them, and ownership is unclear when one misbehaves.

    Agent identityIndustry forumAI accountability
  5. Deception works unusually well against AI attackers.

    Agents enumerate everything, so canaries get touched early. In Tracebit's testing, attacks were detected before the first critical action in 99.4% of runs.

    Presented during the session; related research: Tracebit working paper.

    Deception
  6. Finding vulnerabilities is cheap; proving them is the bottleneck.

    As presented, Mythos found 29,439 vulnerabilities, 6,123 were reviewed and 516 were patched. Human triage is now the rate limit. An independent verifier cut analyst time by 60% in one team's pipeline.

    Figures presented during the session. Public counts from Anthropic change over time.

    AI pentest pipeline
  7. Endpoints now ship AI runtimes attackers can use.

    Chrome downloads a local model (Gemini Nano) onto many machines. Researchers used local models to profile a user's files, decide when to act and hide attack code inside a trusted file, with no malicious file for scanners to find.

    Large Local Malware
  8. Hardware boundaries leak.

    Rowhammer bit flips in NVIDIA GPU memory gave an unprivileged program read and write access to all GPU memory, then root on the host through a driver bug. Model weights and cryptographic keys were exposed.

    Source: GPUBreach, IEEE S&P 2026.

    GPUBreach
  9. AI gateways create confused deputies, and spyware targets people.

    One crafted MCP tool call made an Azure API gateway fetch Key Vault secrets with its own identity. Separately, commercial spyware continues to target journalists, lawyers and activists through zero-click exploits that work on anyone's unpatched phone.

    Azure AI gatewayCitizen Lab keynote
  10. Agents turn requests into decisions nobody approved.

    A request for temporary access ended with an admin console open to the internet, with no attacker involved. The agent's service identity could change network rules and nothing checked the change against the request. Authority has to be enforced at the point of action and preserved across every handoff.

    Real-world parallels cited: Replit's agent deleting production data, and Invariant Labs' GitHub MCP research.

    Who gets to decide?
  11. Long-lived systems carry their old decisions forward.

    A PackBot built in 2021 still ran Python 2.5 on Linux 2.6, with one SSH and web root password shared across the fleet. The research produced six CVEs, one scored 10. Cryptography chosen years ago is the same kind of debt: encrypted data is being harvested now to decrypt once quantum computers can.

    CVSS 10.0: CVE-2026-55393. Canada's federal deadline for post-quantum migration is 2035: ITSM.40.001.

    Hacking the PackBotHarvest now, decrypt later
  12. AI makes defence practice affordable, and takedowns less reliable.

    Open-source labs now let red and blue agents run full purple team exercises that most teams never had budget for. Meanwhile, a ransomware group moved its negotiation portals onto a blockchain where they can't be seized like a server.

    Agentic purple teamingUnseizable extortion

What changed

  • Time. Discovery, exploitation and lateral movement now happen faster than people can respond. Dwell time is no longer a safe assumption.
  • Cost. Finding a vulnerability and running an intrusion both trend toward near zero, so attackers can try low-probability paths at scale.
  • Expertise. Agents and AI-written tooling let less skilled attackers run tradecraft that used to need a funded team.
  • Attack surface. The newest targets are things we already trust: browsers with built-in models, shared GPUs, AI gateways and the phones that hold our credentials.
  • Authority. The actor requesting an outcome, the agent planning it and the identity carrying it out are now often different. Risk comes from what an agent is authorized to cause, not just what it can do.

What organizations should care about

The practical question isn't whether to buy “AI security.” It's whether existing controls still work when attacks move at machine speed. Programs built around detecting and then responding assume time we no longer have. Prevention through architecture (segmentation, least privilege, identity-based access) and automated, pre-approved response for high-confidence signals carry more weight. Inventory is the other recurring theme: you can't govern agents, models, local AI runtimes, long-lived devices or cryptography you haven't found.

Identity implications

Agents and workloads

  • Every agent needs its own credential, scoped permissions, an owner and a tested revocation path.
  • Logs must separate actions taken by an agent from actions taken by the person who triggered it.
  • Workload identities are high-value targets. Require IMDSv2 or equivalent and remove long-lived keys.
  • Gateways that call internal APIs need per-backend identities, not one powerful shared identity.
  • Carry the requester's scope through to the action: an agent's service account must not stand in for the task's authority.
  • Time-boxed access must also reverse what it opened; expiring the credential isn't enough.

People and devices

  • Phishing-resistant authentication (passkeys) assumes a trustworthy device. Spyware and local malware break that assumption.
  • Stolen session tokens bypass strong sign-in. Short token lifetimes and device-bound sessions limit replay.
  • High-risk staff need a defined response to spyware threat notifications, including credential and session revocation.
  • Canary credentials are cheap, high-signal identities worth planting in cloud environments.
  • Fleet-wide shared passwords on devices remove device identity entirely; each device needs its own credential.
  • Passkeys and token signing rely on elliptic-curve signatures; add them to the post-quantum migration inventory.

AI implications

  • Use AI for discovery, but own verification. AI findings are claims until independently proven; unverified volume just moves work onto engineers.
  • Treat local AI as software with permissions. Inventory where models run on endpoints and limit what they can read.
  • Assume prompt injection reaches tools. Anything that can put text in front of an agent can try to steer its tool calls, so authorization must hold even for your own agents.
  • Earn autonomy in security operations. Start with triage and enrichment; keep irreversible actions behind controls that can absorb a bad decision.
  • Don't lock in. Models change quickly; build controls around models rather than into one.
  • Separate reasoning from execution. Let the model propose; let a policy check decide whether the change is in scope before it runs.
  • Practise against AI attackers. Agentic purple team labs show how AI attackers behave against your own detection stack.
